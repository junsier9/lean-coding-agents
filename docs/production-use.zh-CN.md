# Python 维护版使用范围

当前v4已完成303次专项尝试，未达到生产验收，详见[完整结果](../evals/production-2026-10-25/results/v4/summary.zh-CN.md)。`dist/` 中带 `rc` 的文件是审阅验证用候选包；没有正式生产版。最终资格与效率结论分别记录，只有满足验收的版本才进入正式包。

适用请求是对现有 Python 代码进行明确的维护编辑，涉及重复校验、复制、异常、fallback、重试或封装。只读讲解或审查、仅文档修改、其他语言请求不属于本版自动触发范围。运行内容只有 `SKILL.md` 和 `agents/openai.yaml`，没有外部服务、安装依赖或常驻进程。

如需在隔离的 Python 试用项目中验证候选，将解压后的 `lean-coding` 目录放到项目的 `.agents/skills/` 下。保留两文件并用发行清单核对 SHA256；可显式调用 `$lean-coding`，也可以在符合描述的编辑请求中自动选择。项目原有的测试、代码评审和发布授权保持正常运行。

升级时将这两文件作为项目的一次可审查变更，保留之前的已知版本或 Git 提交。需要回滚时恢复旧版的两文件，再核对旧发行清单；旧版副本应放在 skill 发现目录之外，避免同时发现同名版本。本机打包检查会实际解压、恢复 v2、再恢复候选并核对字节，不操作用户的全局 skill 目录。

验证范围为已记录的 Codex CLI、模型配置和 Windows/Python 环境。更换模型、关键项目指令或 skill 后，应重新运行相关契约与对照检查，再使用新的效果结论。Claude 与其他操作系统的原生执行仍待独立验证。

本 skill 指导编程决策，无法替代应用的运行时输入验证、鉴权、事务、错误边界或现有 CI，也不构成自动合并或部署授权。测试通过率和 token 节省是不同证据，具体状态见[本轮协议和结果入口](../evals/production-2026-10-25/README.zh-CN.md)。

可直接使用的请求示例：

- “使用 `$lean-coding`，检查 `parse_order` 与调用者，简化 `handle_order` 中重复的判断，保留入口验证和原来的错误行为。”
- “使用 `$lean-coding`，修复缓存刷新失败被返回旧值的问题；正常查无结果仍允许返回 None，并验证相关失败路径。”

本轮发行按以下证据验收。门槛约束当前评测，不是整个行业的认证标准。

| 证据 | 发行要求 |
|---|---|
| 关键错误边界 | 冻结的关键任务在普通与 `-O` 下所有重复均通过 |
| 原生选择 | 相关编辑加载规则，范围外请求符合预先定义的检查 |
| 真实维护质量 | 两批分别至少 95% 通过、整体不低于基线，且没有任务的成功次数减少 |
| 可重复收益 | 同一个成本指标在两批的单侧 98.75% 成本比上界都低于 1.00；至少 10% 的宣传另需都低于 0.90 |
| 审查与交付 | 预选盲审、数据与原始字节核对、两文件安装及回滚全部完成 |

成本包含失败尝试；token 是报告的输入加输出，缓存输入不重复相加。耗时口径包括 CLI 与独立评分，不包括排队、复制准备和外部审查。测试通过、减少代码冗余、降低 token、节省端到端人工时间分别需要对应证据。
