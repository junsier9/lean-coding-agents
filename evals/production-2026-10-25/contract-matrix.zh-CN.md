# 决策规则与正反任务

当前运行时规则保留在 [v4 冻结候选](candidates/v4-python/SKILL.md)，[v3 历史候选](candidates/v3-python-v2/SKILL.md)原样保留。这里解释如何验收，不随两文件 skill 包加载。正例要求减少没有作用的层；反例要求保留有实际作用的处理。不能用删除行数直接判断成功。

| 决策 | 应当简化的情形 | 必须保留的情形 | 验收任务 |
|---|---|---|---|
| 在使用点证明不变量 | 可信生产者已经验证并返回不可变值，全部到达路径都经过它：避免重复昂贵验证 | 伙伴入口绕过 parser；类型注解不能证明运行时合法；hook 返回后可能已变异 | h01、h02、h10 |
| 复制需要所有权依据 | 已验证的不可变 Manifest 无须再次复制或重新解析 | 报价必须冻结可变输入；hook 可以保留引用，存储结果不能随后改变 | h01、h03、h10 |
| 区分正常缺失与失败 | 约定的 AssetMissing 可返回 False；数据库正常返回 None 可以缓存 | 刷新失败不能回退旧值；未知异常与取消传播；翻译异常保留 cause | h04、h08、h09、h11 |
| 重试需要瞬态且安全 | 已有同一幂等 key 的请求，仅对已知 TransientError 按原界限退避 | 非幂等打印受理结果未知时，标记待核对并传播，不能自动重发 | h05、h06 |
| 复用生命周期与真实边界 | 使用现有 Lease、事务及原子替换接口，避免另造管理框架 | 转账与审计原子性、调用者连接所有权、响应关闭、临时文件清理、取消后的租约释放 | h07、h08、h09 |
| 每次鉴权有真实用途 | 缓存新鲜命中可以省去重复查库 | 命中缓存仍须先鉴权；租户必须隔离；安全的额外鉴权不是功能错误 | h11 |
| 惰性接口不应提前物化 | 按批消费；limit=0 不触碰输入，不预读下一批 | 输入和 sink 的异常立即可见，失败后停止消费；参数边界仍验证 | h12 |
| 封装必须保留已有调用方式 | 复用现有封装机制，避免为不变的转发新增层；内部代理接收者不能截获被包装方法的关键字 | 不能靠元数据伪装修复参数绑定，也不能将原本可按关键字传入的公开接收者改为仅位置参数；验证绑定调用及合法的类调用关键字形式 | 已公开的 cachecontrol-436 开发回归、独立撰写的 [d09](development-next/d09.json) |
| 缺省行为不能吞掉显式输入 | 已声明可选值的选项在裸调用时使用 flag_value | 改变共享解析状态时检查下游消费者；明确附加的 `--opt=--other`、`--opt=-3` 仍须作为原值消费，不能因选项前缀误入缺省分支 | [v4 预选盲审 pair05 的确认回归](results/v4/blind-pair05-adjudication.json)；当前候选未通过此项 |
| 完成相关验证后结束 | 运行项目要求和与改动相关的正常、失败路径检查 | 发生具体失败或跨越新边界时扩大检查；不能仅用可被 -O 移除的 assert 做输入验证 | 全部关键任务 |

12 题的参考版本在普通与 `-O` 模式分别通过 121 项检查；初始版本每题至少一项失败。首轮 v3 执行为每题两组各三次，共 72 次原生会话。v4 使用同一批已知关键契约，仅对当前候选各复测三次，共 36 次，不能称为新封存验收。每组累计 726 次检查执行并不等于 726 个独立案例。

封装调用方式的开发回归保留三轮实际结果：3/6、5/6、最终 [6/6](results/v4/development-iteration3.json)。旧失败包括内部代理截获原接收者关键字，以及把公开接收者改为仅位置参数；[修订记录](results/v4/development-revision3.json)解释了窄范围修正。cachecontrol-436 的 49 项检查和 d09 在普通、`-O` 下各 15 项检查用于开发回归，不计入新 40 题的独立效率样本。

另有自动选择检查：3 个相关 Python 编辑请求、6 个范围外请求。前者复用开发题，后者包括独立撰写的只读请求；这组结果只检验这些请求的可见加载与编辑行为，不估计全体请求的误触发率。

真实项目质量与成本通过两批各 20 题的独立对照验收，不能由上述合成题通过直接推导。详情见 [v3 协议](protocol.json)、[v4 协议](protocol-v4.json)、[发布要求](results/release-requirements.json)与[本轮入口](README.zh-CN.md)。
