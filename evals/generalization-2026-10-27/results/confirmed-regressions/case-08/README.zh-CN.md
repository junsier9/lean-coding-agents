# case-08：多值选项补全兼容回归

这是本轮固定 r0 产物的独立审查发现，属于看过产物后新增的诊断测试，**不属于原冻结评分器，也没有用于修改本轮候选或重新评分**。原独立报告及输入哈希会随本轮验收结果保留。

原需求是让 `nargs>1` 的选项在仍等待输入值时获得自己的补全候选，不受之前布尔标志干扰。候选扫描到最近以选项前缀开头的 token 就返回，因而将该选项已接受的合法值 `-1`、`-`、`--flag` 当成另一个选项。

最小例子：`--flag --pair -1` 还缺 `--pair` 的第二个值。两版完整解析 `--flag --pair -1 1 rest` 均得到 `pair=('-1', '1')`，但原版此时补全返回 `['-1', '1', '2']`，候选返回位置参数候选 `['rest']`。独立审查确认 1 个 P2；父代理另用最小探针复现了相同差异。

- `test_option_like_values.py`：3 种合法前缀值 × 有无之前的标志，共 6 例；审查副本原版 6 passed，候选 6 failed。
- `parent_probe.py`：父代理最小复现。用本轮 Python 执行，依次传入待检查版本的 `src` 目录和冻结 `testdeps` 目录。
- `parent-confirmation.json`：父代理实际观测结果及探针 SHA256。

运行六例测试时，须将待检查版本的 `src` 与冻结 `testdeps` 放在该进程的 `PYTHONPATH`，禁用额外 pytest 插件自动加载，再执行 `python -B -m pytest -p pytest_timeout --timeout=30 -q test_option_like_values.py`。原始 base、候选完整源码和执行日志保留在本轮私有审查及工作区归档；公开候选补丁见本轮 `patches/`。

这项发现使“8 份预选审查、零确认缺陷”的门槛不能通过。它是使用 skill 后某份产物的失败，不足以单独证明由 skill 导致；本批次没有无 skill 对照臂。
