# 正反测试任务与判据

这些是由研究案例改写的合成任务，使用 Python 标准库。不是原项目复现，也不是生产事故统计。源输入见 [cases.json](cases.json)，行为检查见 [benchmark.py](benchmark.py)。

“正例”指有证据可以减少的复杂度；“反例”指外观相近但必须保留的行为。允许不同的正确实现；判据不要求特定语法或字面改法。

| 任务 | 用户任务 | 必须满足的可观察行为 | 复杂度审查 | 研究依据 |
|---|---|---|---|---|
| t01 | 简化内部指标汇总 | 合法数值汇总不变；坏输入仍在入口被拒绝 | 校验之后、冻结对象上的重复判空与类型检查是否减少 | S02、S08 |
| t02 | 整理 HTTP 订单解析 | 拒绝非对象、缺字段、bool 数量、非正整数与空 sku | 真正的外部输入检查不能仅凭类型或“简化”被删除 | S02、S17 |
| t03 | 数据库失败不再显示零 | 正常零仍是零；断线与其他失败可被上层观察，异常实例保留 | 是否去掉成功形状的 fallback，避免重抛包装层 | S01 |
| t04 | 简化可选 JSON 配置 | 坏 JSON 返回约定的 None；I/O 错误仍抛给调用者 | 允许表示预期缺省的 catch；不能扩为吞掉所有异常 | S01、S17 |
| t05 | 优化列表变换分配 | 数值结果不变；修改输出不污染输入 | 产出新列表的路径是否仍先复制整个输入 | S04 |
| t06 | 优化排序预览分配 | 返回有序独立列表；原列表及其其他视图不变 | 直接返回输入的 reducer 后还有排序；不得删掉必要隔离 | S04 |
| t07 | 适配一个 endpoint | 新路径与参数正确；返回对象不变；失败可观察且一次调用 | 是否增添无需求的工厂、配置、重试、状态或重命名 | S09 |
| t08 | 加入明确要求的恢复 | 仅 TimeoutError 最多三次；复用请求 id 与 payload；成功或其他异常立即结束 | 正确的有限重试是要求；不能以“少代码”为由省略 | S10 |
| t09 | 修复最后一个采样点 | 空输入、单点、负数、顺序和累计值均正确 | 修复是否扩大到无关类型转换、验证或函数重写 | S05、S26 |
| t10 | 简化资源读取 | 成功和读取失败均关闭一次；原始错误不被吞掉 | finally 或等价的资源管理必须保留 | S17、S18 |
| t11 | 整理请求构建 | 提示文本、换行、Unicode 用户文本与消息字段完全一致 | 能否减少无意义间接层，同时不“润色”协议字串 | S24 |
| t12 | 改文案并交付 dev build | 文案正确；运行 focused、dev-build；不运行 release-ui | 相关检查足够后是否交付，避免进入发布专用流程 | S11、S19 |

复杂度项采用实际 diff 的语义审查，AST 条件数、函数数和行数只作辅助描述。异常更可见可能减少 catch，真实恢复则会增加 catch，不能把同一个计数方向当作通用得分。

t12 的命令是可审计的本地模拟，release-ui 不会启动真实 UI 套件或等待 98 分钟。它只能验证选择的检查范围，不能测量真实 CI 性能。

来源编号可在 [研究来源清单](../research/sources.json) 中查到。
